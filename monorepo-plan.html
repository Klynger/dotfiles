Dotfiles Monorepo Plan

Merging dotfiles (shared + macOS) and hyprland-desktop-config (CachyOS + Hyprland) into one repo that installs safely on both machines. Written 2026-09-10, from an audit of both working trees. Legend: general macos linux done

Where things stand

Two repos configure two machines. dotfiles was born on the Mac: its installers assume Homebrew and Xcode CLI tools, and some of its symlinks would break the Linux desktop if created there. hyprland-desktop-config owns the Linux desktop (Hyprland, waybar, rofi, GTK, pipewire) and has its own copy of the symlink machinery, plus root-copy and webapp mechanisms dotfiles lacks. They clash in three places: both configure wezterm, both carry a symlinks.conf + script pair, and both have their own AGENTS.md and .gitignore.

Groundwork already merged today, which this plan builds on:

  • done Symlinks split into symlinks/general.conf + symlinks/macos.conf, with symlinks.sh selecting by uname (PR #2).
  • done tmux clipboard made cross-platform; tpm plugins moved under the repo (PR #7).
  • done yazi config trimmed to overrides only (PR #8).
  • done kitty and VS Code configs removed entirely; the terminal on both machines is wezterm, the editor is Neovim.

implementation status

Phase 0 is executed: both repos carry a pushed pre-monorepo tag. Phases 1–4 are implemented as a stack of PRs, each based on the previous: #9 (kitty/vscode cleanup, the stack base) ← #10 (phase 1) ← #11 (phase 2) ← #12 (phase 3) ← #13 (phase 4). Merge them top-down; the machine migrations run at their phase’s exit point as planned.

Target shape

Shared configuration stays at the repo root, which keeps existing paths and history quiet; the OS “branches” become two directories, each dead code on the other machine by design. 

dotfiles/
├── install.sh              # detects OS, runs the right side
├── symlinks/
│   ├── general.conf        # done
│   ├── macos.conf          # done
│   └── linux.conf          # returns in phase 4
├── scripts/                # OS-agnostic machinery only
│   ├── migrate_macos.sh    # one-shot, phase 3; removed in phase 5
│   └── migrate_linux.sh    # one-shot, phase 4; removed in phase 5
├── nvim/  tmux/  yazi/  vim/  ai/   # general, stay at root
├── macos/
│   ├── wezterm/  rectangle/
│   └── scripts/            # brew installers, prerequisites
└── linux/                  # hyprland-desktop-config, imported with history
    ├── hypr/  waybar/  rofi/  swaync/  gtk-3.0/ …
    └── scripts/            # copies-root, webapps, hypr_copies
Phase 0

Checkpoint both repos

Every later phase has a known-good state to fall back to.

  • Tag the current main of both repos and push the tags: git tag pre-monorepo && git push origin pre-monorepo in dotfiles and in hyprland-desktop-config.
  • These tags are the rollback anchors: either machine can return to today’s working setup with git checkout pre-monorepo followed by ./scripts/symlinks.sh --create (plus the other repo’s own scripts on Linux).
  • From here on, hyprland-desktop-config is frozen: no new commits land there, so the phase 4 import does not chase a moving target.
  • No prep PR is needed in hyprland-desktop-config before the import; an audit (2026-09-10) confirmed it is move-in ready: no config or script hardcodes the repo path (everything resolves through $HOME symlink and copy targets, and the confs use $(pwd)), host-specific files like monitors.lua are copy-based and gitignored by design, and local noise such as .claude/settings.local.json is untracked so the import cannot pick it up. The only references to the repo’s own name sit in AGENTS.md, which phase 4 merges anyway.
Phase 1

Move macOS trees under macos/

After this phase the repo root contains only configuration that is true on both machines.

  • git mv wezterm/ and rectangle/ into macos/.
  • Update the wezterm source path in symlinks/macos.conf. The target (~/.wezterm.lua) does not change.
  • Nothing on the Linux machine changes; its run only reads general.conf.

mac rollout

Existing Mac symlinks point at the old paths and become dangling after the move. Nothing is done by hand: the MacBook keeps running on its current checkout until phase 3, when migrate_macos.sh performs the whole switch in one run.

Phase 2

Split the install scripts

Running ./install.sh on either machine is safe and does only what belongs there.

  • Move scripts/prerequisites/ (Xcode) and the cask installers (wezterm, fonts) to macos/scripts/.
  • Keep symlinks.sh, utils.sh, check_requirements.sh and the formula-based installers (fzf, nvim, tmux, yazi, zsh) in scripts/ as shared machinery; CLI tools come from brew on both OSes.
  • Rewrite install.sh as a small dispatcher: detect_os (already in utils.sh), then macOS runs prerequisites + all installers + symlinks; Linux runs the formula installers + requirement checks + symlinks, while desktop packages stay with pacman.
  • The “how to install” hints in requirements.conf need no OS variants: with the linuxbrew decision, brew install… is correct on both machines.
Phase 3

Docs, verification and the Mac migration

The split is documented, provably safe, and the MacBook runs on the new structure.

  • Update README.md and AGENTS.md: new layout, the general/macos/linux contract, where new configs go.
  • Add a fake-$HOME smoke test (the trick already used to validate the symlink split): run create + delete against a throwaway home on each OS path and assert the exact link set.
  • Write scripts/migrate_macos.sh, a one-shot script run once on the MacBook:
    1. Refuse to run unless on macOS with a clean working tree, then git pull.
    2. Remove symlinks in $HOME that point into the repo’s old layout, including the now-dangling ~/.config/kitty left from the kitty removal.
    3. Run symlinks.sh --create against the new confs, then check_requirements.sh.
    4. Print every link it deleted and created, so the run is auditable against the rollback tag.
  • Exit criterion for the phase: migrate_macos.sh has run on the MacBook and a new terminal + nvim + tmux session works there. Rollback if not: git checkout pre-monorepo and recreate links.
Phase 4

Import hyprland-desktop-config as linux/

One repo owns both machines; the full hyprland-desktop-config history comes along.

  • Import with history, via filter-repo so old commits are browsable with plain git log:
    1. Fresh clone of hyprland-desktop-config (filter-repo rewrites in place, never touch the real checkout).
    2. git filter-repo --to-subdirectory-filter linux in that clone: every historical path is rewritten under linux/.
    3. In dotfiles: git remote add hypr <clone>, git fetch hypr, git merge --allow-unrelated-histories hypr/main, drop the remote.
  • Why not git subtree add: it also keeps the commits, but their paths stay unprefixed, so git log linux/hypr/ shows nothing before the merge and every lookup needs --follow tricks. The rewrite makes history first-class. Original untouched hashes remain reachable through the frozen repo’s pre-monorepo tag.
  • Recreate symlinks/linux.conf from that repo’s symlinks.conf, with sources under linux/; retire its private copy of the symlink script in favor of the shared one.
  • Port its extra machinery under linux/scripts/: copies-root.conf (sudo copies for sddm etc.), basefiles.conf, webapps.conf, hypr_copies. These stay copy-based, not symlink-based, on purpose.
  • Resolve the wezterm clash by keeping the two configs fully separate: macos/wezterm → ~/.wezterm.lua and linux/wezterm → ~/.config/wezterm. They serve different setups and won’t converge, so no shared module.
  • Merge AGENTS.md and .gitignore; the Linux one ignores generated matugen output that must stay ignored.
  • Write scripts/migrate_linux.sh, the one-shot counterpart for this machine, run once after the merge lands:
    1. Refuse to run unless on Linux, the working tree is clean, and linux/ exists in the checkout.
    2. Remove symlinks in $HOME that point into ~/dev/hyprland-desktop-config (~/.config/hypr, ~/.profile, ~/.config/wezterm, …) and recreate them from symlinks/general.conf + symlinks/linux.conf.
    3. Re-run the copy-based steps from linux/scripts/: hypr_copies, and copies-root.conf targets with sudo (sddm etc.).
    4. Reload the live session (hyprctl reload, restart waybar) and print the audit of every link changed.

risk

This is the one phase that touches the live Hyprland session. Run migrate_linux.sh from a terminal that survives a compositor reload, keep the old repo checkout untouched until the new links are verified (it is also the pre-monorepo rollback anchor), and only then proceed to phase 5.

Phase 5

Decommission the old repo

One source of truth remains.

  • Archive Klynger/hyprland-desktop-config on GitHub with a pointer to dotfiles/linux/.
  • Remove the local ~/dev/hyprland-desktop-config checkout after a full reboot-and-verify cycle on the Linux machine.
  • Final pass on both machines: ./install.sh from scratch in a fake $HOME, then for real.
  • Delete the two one-shot migration scripts; the pre-monorepo tags stay forever as the historical checkpoint.

Open decisions

  • Brew on Linux: decided. CLI tools the dotfiles manage come from linuxbrew on both machines, provided the bottle is current. tmux moved on 2026-09-10 (brew 3.7c matches upstream 3.7c; the pacman copy can be removed with sudo pacman -Rns tmux); nvim was already linuxbrew. Desktop packages (Hyprland, waybar, …) stay with pacman.
