Quickshell Migration Plan

Replace the loose desktop pieces (waybar, swaync, rofi, wlogout, quick-panel, hyprlock) with one quickshell shell owned in this repo. The goal is connectedness: every widget, key, and panel reading the same state. The look is a separate, swappable layer; liquid glass is the first skin, not the point.

Principles

  • Own it. The shell lives in linux/quickshell/, written here, with no upstream to track. Vitreus and Serpantinum are references to study, never code to vendor.
  • Core before skin. Services (the connected part) and theme (the look) are separate layers from the first commit, so the design can be replaced later by editing tokens and a few primitives, touching no feature.
  • Function-first cutovers. A long ugly middle is accepted. Each old component is retired the day its replacement works better, regardless of how it looks. Beauty is its own phase at the end.
  • One PR per phase. Same workflow as the monorepo migration: a stack on GitHub, each phase usable on its own, nothing breaking the daily driver. The old stack stays installed until the cleanup phase.

Architecture

One qs process, started from Hyprland's autostart, driven by key binds through qs ipc. Three layers inside, strictly ordered by how permanent they are:

services/ · permanent

Singletons with no visuals: Audio (Pipewire sinks and per-app streams), Network, Bluetooth, Notifications, Media (Mpris), Workspaces (Hyprland), Brightness, Tray, Power. This is the single state tree that makes the mute key, the bar icon, the mixer slider, and the OSD agree by construction.

modules/ · stable

The features: Bar, Notifications, Controls, PowerMenu, Launcher, Dashboard, OSD, WallpaperPicker, Lock. Modules compose primitives and talk to services; they never hardcode a color, a font, or a shape.

components/ + Theme · disposable

A Theme singleton (colors, radii, blur, fonts, animation curves) and a dozen primitives (Panel, Drawer, Slider, Button, Icon) built from it. Restyling the desktop means editing this layer only. Liquid glass is the first value these tokens take.

Phases

0

Scaffold

Install the quickshell package, add the linux/quickshell symlink and the autostart entry, and land the skeleton: Theme singleton with a flat placeholder palette, the first service (Workspaces), and an empty bar window proving layer-shell, IPC, and hot reload work.

Done when qs runs at login next to the current stack.

1

Bar

A plain, functional bar: workspaces, clock, system tray, volume, network, notification count. Audio, Network, and Tray services land here. Runs beside waybar until it covers everything used daily.

Done when the bar is better than waybar. Retire waybar.

2

Notifications

The shell becomes the notification server: popups, a history drawer from the bar, do-not-disturb. This is an atomic swap (two servers cannot share the DBus name), so it cuts over in one go.

Done when nothing is missed for a week. Retire swaync.

3

Controls and power

A controls drawer: Wi-Fi, Bluetooth, per-app volume mixer, brightness, DND, and session actions (lock, logout, reboot, poweroff). The mute-everything key gets its connected implementation here, with instant feedback in every widget.

Done when the drawer replaces daily pavucontrol/bluetui trips. Retire wlogout and most of quick-panel.

4

Launcher

App launching first, matching rofi's speed and fuzziness; then the extras worth having (calculator, clipboard history). Bound to the same key the whole time.

Done when rofi stops being opened on purpose. Retire rofi.

5

Dashboard, OSDs, wallpaper

Volume and brightness OSDs on the media keys, a dashboard view with what remains of quick-panel, and a wallpaper picker driving swww.

Done when the scripts are unused. Retire quick-panel and the picker scripts.

6

Lock screen

WlSessionLock lock screen wired to hypridle. Highest risk, so it goes last and hyprlock stays installed as the fallback until the new lock has proven itself.

Done when lock, idle-lock, and unlock are boring. Retire the hyprlock bind.

7

Design pass: the glass skin

The placeholder look is replaced by liquid glass through the Theme and primitives only: translucency, Hyprland blur rules per layer namespace, springs on the drawers, and optionally the hyprglass plugin for real refraction. Vitreus is the visual reference. That no module file changes in this phase is the proof the skin is swappable later. One module earns an exception: the wallpaper picker gets a showpiece presentation (animated tiles, live preview while stepping through, in the spirit of the Vitreus and Serpantinum pickers), explicitly wished for during phase 5.

Done when the desktop looks intentional and the diff touches only the theme layer.

8

Cleanup

Remove the retired packages from prerequisites/install.sh, drop their symlinks and config directories, retire the shell-facing matugen templates, update the VM test assertions to check the quickshell config instead of waybar's CSS, and rewrite the relevant README and AGENTS.md sections.

Done when test-arch.sh passes on a fresh VM with the new stack.

Open decisions

  • Matugen's fate. The shell stops needing it in phase 8, but wezterm, btop, gtk, and the sddm theme still consume its output. Options: keep a slimmed matugen for those, or go fully static (Tokyo Night day/night pairs, keeping toggle-theme-mode meaningful). Decide by phase 7.
  • Wallpaper-driven color. Dropping Material design does not force dropping wallpaper-driven color; the Theme singleton could take its accent from the wallpaper without matugen. Default plan: fixed palette.
  • Keybind collisions. New surfaces want keys (dashboard, controls). Assign them when each module lands; nothing is reserved up front.
  • sddm. Out of scope. A quickshell greeter via greetd exists as a possibility, but only after the shell has been stable for a while.

References

  • Vitreus (MIT, pleamar): the design north star for the bar-with-drawers interaction model. Ideas and even assets can be borrowed.
  • Serpantinum (AGPL, quickshell): the best study material for how quickshell solves each problem, including a pure-QML liquid glass shader. Study only; no code copied into this repo.
  • hyprglass (BSD, Hyprland plugin): compositor-level refraction per layer namespace, configured in the same Lua DSL as linux/hypr/. Optional, for the glass phase.
  • Quickshell documentation: services, layer-shell windows, WlSessionLock, IPC.
